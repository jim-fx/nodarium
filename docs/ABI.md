# Nodarium Node ABI v1

A node is a WebAssembly module. Any language that can produce a `.wasm` file with the exports below can implement a node. Rust nodes get all of this generated by `#[nodarium_execute]`.

## Units

- Pointers are byte offsets into the module's own exported `memory`.
- Data is exchanged as `i32` words. Every length (`len`) counts **i32 words**, except `nodarium_alloc`, which takes **bytes**.
- All pointers handed to the host must be 4-byte aligned.

## Exports

| Export                                          | Description                                                                                                                                                                                                                                                                             |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `memory`                                        | The module's linear memory.                                                                                                                                                                                                                                                             |
| `nodarium_alloc(bytes: i32) -> ptr`             | Allocates `bytes` of 4-byte aligned memory. It must stay valid until the next `nodarium_reset`.                                                                                                                                                                                         |
| `nodarium_reset()`                              | Frees everything allocated or returned since the last reset. The host calls it once per graph execution, before the first node runs.                                                                                                                                                    |
| `nodarium_execute(args: ptr, argc: i32) -> ptr` | Runs the node. `args` points to `argc` pairs of `[ptr: u32, len: u32]`, one pair per input, in the order of the definition's `inputs`. Returns a pointer to a `[ptr: u32, len: u32]` pair describing the result. The result must stay valid until the next reset. Inputs are read-only. |

## Imports (`env`)

| Import                               | Description                                    |
| ------------------------------------ | ---------------------------------------------- |
| `nodarium_log(ptr: i32, len: i32)`   | Logs `len` bytes of UTF-8 text at `ptr`.       |
| `nodarium_panic(ptr: i32, len: i32)` | Reports a fatal error message before trapping. |

## Definition

The node definition JSON (see [NODE_DEFINITION.md](./NODE_DEFINITION.md)) is stored as UTF-8 in a custom section named `nodarium_definition`.

## Values

Each input is either a single word (`float` encoded as its f32 bits, `integer`, `boolean`, `select` index, `seed`) or a bracket-encoded array (see `packages/utils/src/flatTree.ts`). Results of other nodes are passed through unchanged, so a node receives exactly what its input node returned.

## Execution model

Within one graph execution the host:

1. calls `nodarium_reset()` on every module used by the graph
2. for each node, bottom up:
   - allocates and fills its inputs with `nodarium_alloc`. A result of the same module is passed by pointer without copying; results of other modules are copied directly from that module's memory.
   - writes the argument table (also via `nodarium_alloc`) and calls `nodarium_execute`

The host only copies results out of wasm memory when it needs them to outlive the execution: the final output, cached results, and debug data.

## Legacy ABI

Modules that export `execute`, `__alloc` and `__free` instead of `nodarium_execute` are still supported by the host. They receive all inputs concatenated into a single bracket-encoded array, and their result is copied into JS memory after every call.
